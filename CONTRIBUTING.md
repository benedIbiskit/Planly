# Правила работы в команде

## Git-стратегия

Используем GitHub Flow: изменения выполняются в отдельных ветках и попадают в `main` через Pull Request после ревью.

### Ветвление

- `main` — стабильная версия.
- `feature/[название]` — новые функции (например, `feature/initial-setup`).
- `bugfix/[название]` — исправление багов.

Перед началом работы обновите локальную стабильную ветку:

```bash
git switch main
git pull --ff-only origin main
git switch -c feature/my-feature
```

### Коммиты

Используем [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` новая функция.
- `fix:` исправление бага.
- `docs:` изменения в документации.
- `style:` форматирование кода.
- `refactor:` рефакторинг.
- `test:` добавление тестов.
- `chore:` рутинные задачи.

Пример: `feat: add initial FastAPI application with health check`.
Один коммит должен содержать одно осмысленное изменение. Секреты, виртуальное окружение и локальные базы данных в репозиторий не загружаем.

## Code Review

- Каждый PR требует минимум одно одобрение (`Approve`) от другого участника команды.
- В описании PR укажите, что изменилось, зачем и как проверялся результат.
- Ревьюер проверяет стиль кода, архитектуру, работоспособность и достаточность проверок.
- Автор отвечает на все комментарии и исправляет согласованные замечания.
- Слияние в `main` выполняется после одобрения; автор не подменяет ревью самостоятельным подтверждением.

Для практики №1 проверьте установку зависимостей в чистом окружении, запуск `uvicorn main:app --reload`, ответы `/` и `/health`, страницы `/docs` и `/openapi.json`.

## Встречи команды

Предлагаемый порядок для согласования участниками:

- Частота: два раза в неделю; конкретное время согласуем в GitHub Issues.
- Канал связи: [Issues проекта](https://github.com/benedIbiskit/Planly/issues) и обсуждения Pull Request.
- Время ответа на сообщения: в течение 24 часов.

## Разрешение конфликтов

1. Обсуждение в команде с фиксацией аргументов в Issue или PR.
2. Голосование участников: решение большинством голосов.
3. Если договориться не удалось — обращение к преподавателю `andrey-limasov`.
